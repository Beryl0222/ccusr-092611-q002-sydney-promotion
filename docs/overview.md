# 悉尼文旅推介协作库说明

悉尼文旅推介协作库需要在多方参与、事件顺序不稳定和服务重启的情况下保持记录一致。每条记录有所属方、状态和递增版本,所有状态变化写入事件表;请求键用于抵御重复提交,事务失败时整次写入回滚。

## 业务规则

- **机构隔离**:机构分主办方(center)与合作机构(partner)。展项由其负责机构维护,主办方负责审定、授权、窗口与配额;合作机构只能操作自己负责或被授权给自己的内容。
- **展项版本**:展项携带递增版本号。并行修改同一展项时,版本一致直接落库;版本落后但与期间修改的字段不相交则自动合并,字段相交则拒绝并提示当前版本,由提交方基于最新版本重试。
- **翻译稿**:中文原稿随展项保存,其余语种译稿各自独立版本、先后到达。译稿经负责机构提交、主办方确认后才可进入发布包;已确认译稿被修改后回到草稿,需重新确认。
- **授权**:主办方把已审定展项在有效期内授权给合作机构。授权过期或被撤回后,不能再据此生成发布包。展项内容变化会为仍在有效期内的授权生成待确认记录,对方确认前该展项不可发布。
- **发布窗口与配额**:发布包只能在对应城市的开放窗口内生成,并按发布条目扣减机构配额;配额不足或任一校验失败时整批回滚。
- **幂等发布**:发布请求携带批次键,同一机构同一批次键重放返回原发布包,不重复扣减配额;同键不同请求被拒绝。
- **交接恢复**:主办方为合作机构建立交接单,逐条签收。合作方离线后重新上线时,通过交接单恢复未完成条目;重复签收幂等,全部签收后交接完成。
- **清单核验**:按城市和语言汇总最终发布清单,每条目带内容 SHA-256 校验和,清单整体另有摘要;合作方可重新计算摘要比对,确认拿到的清单与主办方一致。

## 接口一览

| 方法与路径 | 说明 |
| --- | --- |
| POST /orgs | 登记机构(引导操作,免身份头) |
| POST /exhibits,GET /exhibits,GET /exhibits/{id} | 登记/列表/详情 |
| POST /exhibits/{id}/update | 修改内容(版本校验,自动合并或拒绝) |
| POST /exhibits/{id}/state | submit/approve/reject/archive |
| PUT /exhibits/{id}/translations/{lang} | 上传或修改译稿 |
| POST .../translations/{lang}/submit、/confirm | 译稿提交与确认 |
| POST /grants,POST /grants/{id}/revoke,GET /grants/{id} | 授权签发、撤回、查询 |
| GET /authorizations | 授权总览(含待确认修改) |
| GET /changes,POST /changes/{id}/confirm、/reject | 修改确认处理 |
| POST /windows,POST /windows/{id}/close | 发布窗口开关 |
| POST /quotas,GET /quotas | 配额设置与查询 |
| POST /packages,GET /packages/{id} | 生成发布包(批次键幂等) |
| POST /handoffs,GET /handoffs,GET /handoffs/{id},POST /handoffs/{id}/ack | 交接单与断点恢复 |
| GET /manifest,GET /manifest/verify | 按城市/语言的最终清单与摘要核验 |
| GET /events/{entity} | 事件流水(主办方) |

错误映射:400 参数无效,401 缺少身份头,403 无权操作,404 不存在,409 版本或幂等键冲突,422 状态不允许。
